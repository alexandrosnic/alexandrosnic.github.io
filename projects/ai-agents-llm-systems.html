LLM-powered AI Agents for Robotic systems

Lead developer of a robotic startup's AI agent stack

Description

I designed and implemented the AI agent stack as an LLM-based troubleshooting and diagnostics layer for Conbotics painting robots. Rather than using simple prompts, the system utilizes a multi-agent orchestration architecture to plan, clarify, search, and troubleshoot complex operational issues.

The system features a **Router Agent** to classify incoming queries and detect intents, a **Clarification Agent** to resolve diagnostic gaps, and a **Troubleshooting Agent** executing local RAG. If RAG is insufficient, the system uses a general query classifier to route queries either to web scraping tools or Conbotics support. Additionally, a background crystallization process runs asynchronously in a daemon thread to distill session outcomes into semantic wiki facts without blocking the interface.

Key Architecture Implemented

  • Multi-Agent Orchestration: Implemented a pipeline dividing queries between Router, Clarification, and Troubleshooting agents to handle vague diagnostic details deterministically.
  • Asynchronous Session Crystallization: Engineered a daemon-thread based knowledge synthesis pipeline that processes chat sessions to automatically promote high-confidence facts to the semantic wiki database.
  • Semantic Query Expansion & RAG: Tuned hybrid search weighting (BM25 + Cosine similarity embeddings via nomic-embed-text) and structured semantic query expansion to eliminate follow-up query context drift.
  • Deterministic Loop Guarding: Added strict state tracking to detect and prevent repeating agent clarification patterns when operators report that diagnostic indicators are unavailable.

Technologies Used

  • Ollama (Local LLM & Embedding Inference)
  • Qwen2.5-7B & Nomic-Embed-Text
  • ChromaDB Vector Store + BM25 Hybrid Search
  • Asynchronous Multi-threading (Python Daemon Threads)
  • Streamlit Frontend UI
  • Docker / Docker Compose (NVIDIA GPU Container Runtime)
  • Python
